# v2.8.0 — Full Persistent Workspace Database

- Replaced the previous split persistence model with one async SQLite/Turso database adapter.
- With Turso configured, all core application records use the remote libSQL database.
- Local SQLite remains an automatic zero-config fallback for development.
- Registration, login, sessions, forgot-password codes and workspace records now share the same `users` table and stable user IDs.
- Full schema is initialized automatically on first connection.
- Existing safe schema migrations still run at startup.
- Transaction support works for local SQLite and Turso transaction clients.
- Readiness endpoint exposes `database_storage` and `persistent` status.
- Production startup logs whether Turso persistence is active.
- Local reset helper refuses to run when Turso credentials are present.
- Docker no longer declares the container data folder as the production persistence mechanism.
- `@libsql/client` added for remote libSQL access.
